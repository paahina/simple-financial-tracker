### 3.1. Return visit — refresh data without full page reload
**Priority:** High | **Status:** [x]

**Problem (agreed):**
- After not using the app for ~a day (tab in background, closed browser, or cold API on Render), users
  can see stale dashboard/lists or wait on the session gate. We already **auto-retry session**; we do
  **not** use `location.reload()`.
- Goal: when the user comes back after **long idle**, **refetch ledger-related data in the SPA** so
  balances and lists match the server without a hard browser refresh.

**Out of scope:**
- `window.location.reload()` or forced full document reload.
- Replacing session auto-retry in `AuthContext.jsx`.
- Redis / server cache layer (see docs/15_caching_rules.txt — planned separately).
- PersistQueryClient / offline cache (optional follow-up).

**Approach (agreed):**
1. Track **last time the tab went hidden** (`visibilitychange` → hidden, plus `pagehide` as backup) in
   `localStorage` (`tracker_last_hidden_at`).
2. **Idle threshold:** 24 hours — if the user returns (tab visible again **or** authenticated shell mounts
   and last hidden ≥ 24h ago), invalidate TanStack Query families used for money UI.
3. **Invalidation:** reuse `invalidateFamilies` pattern — reset/refetch active queries for:
   `dashboard`, `accounts`, `categories`, `transactions`, `transfers`, `debts`, `to-buy`, `reports`.
4. Hook lives on authenticated shell (`UserLayout`) so guest/sign-in routes are unaffected.
5. Keep default **`refetchOnWindowFocus`** behavior (React Query) for shorter idle; 24h path is the
   explicit “was away a long time” safety net.

**Implementation notes:**
- Constants in `src/query/cache.js`: `IDLE_REFRESH_MS`, `LAST_HIDDEN_STORAGE_KEY`, `refreshLedgerAfterIdle()`.
- Hook: `src/hooks/useRefreshLedgerAfterIdle.js` — visibility + mount check; no UI spinner (queries show
  existing skeletons while refetching).
- Do not invalidate auth/session queries.

**Acceptance criteria:**
- No `location.reload()` added anywhere for this feature.
- Tab hidden ≥ 24h then focused: active page data refetches (network tab shows GETs); UI updates without
  manual browser refresh.
- Idle &lt; 24h: no extra full-family reset beyond normal React Query focus/stale behavior.
- Session cold start still uses existing retry skeleton; this change does not remove **Try again**.
- Sign-in / guest routes do not run ledger invalidation.

**QA edge cases:**
- Open app in two tabs; hidden time is shared via localStorage — both refresh when stale (acceptable).
- User on form overlay mid-edit; refetch should not navigate away (only query data updates).
- 401 on refetch still handled per existing API/auth flows.
