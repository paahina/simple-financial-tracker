PRIORITY G — Debt payment + optional INCOME transaction
----------------------------------------------------------------------

G1. Optional “also record as income” on debt payment create/edit
    Problem: Debt payments increase account balance and reduce debt, but do
    not appear as INCOME in transaction lists / income reporting unless
    duplicated manually.
    Agreed behavior:
    [x] On Record payment (and edit): optional checkbox, e.g. “Also record as
        income”. NOT a transfer — only DebtPayment + Transaction type INCOME.
    [x] When checked on save: create two separate objects in one action:
        (1) DebtPayment — unchanged role (debt remaining, account, amount,
            paymentDate, notes).
        (2) Transaction — type INCOME, same accountId, same amount, same
            date; user supplies income categoryId and label (notes may copy
            to description). Two Mongo documents, one user submit.
    [x] When unchecked: only DebtPayment (current behavior).
    [x] Link records (e.g. transactionId on DebtPayment or debtPaymentId on
        Transaction) so balance is not double-counted: account balance counts
        the money once (prefer INCOME transaction; exclude linked payment from
        debtPayments sum in balanceForAccount). Debt remaining still sums all
        DebtPayment amounts.
    [x] Update/delete payment: keep linked transaction in sync (amount, date,
        account, category/label). Deleting the payment deletes the linked
        income too; the income row cannot be edited from Transactions.
    Files: debtPaymentModel.js, debtController.js, transactionController.js
           or shared service, finance.js (balanceForAccount), validationMiddleware,
           DebtPaymentCreatePage.jsx, PaymentEditPage.jsx, api.js.
    QA: Payment without checkbox — balance + debt only. With checkbox — debt
        reduced, one INCOME row, balance same as without double-count. Edit/
        delete pairs. 401/inactive account unchanged.

PRIORITY H — Account sub-balances (envelopes inside one account)
----------------------------------------------------------------------

H1. Data model and account CRUD for sub-balances
    Problem: User wants named slices of one account balance (e.g. BPI total
    PHP 3,500 with “Savings” PHP 200 and more labels), not separate accounts.
    Agreed behavior:
    [x] Per account: at least one sub-balance (default label “Current”).
        Account total is the sum of pockets. Current amount on create/edit is
        read-only. Remaining-balance chip still uses that total.
    [x] Manage on account create/edit (add/rename/remove rows; cannot remove
        the last row). Lazy backfill Current on read for older accounts.
    [x] Distinct from remainingBalance (low-balance alert threshold).
    Files: accountModel.js, accountController.js, AccountCreatePage.jsx,
           AccountEditPage.jsx, AccountsPage.jsx (optional breakdown display).

H2. Transactions use sub-balance when account has envelopes
    [x] After user picks Account on transaction create/edit: if that account
        has sub-balances, require picker — “Deduct from” / “Add to” pocket.
    [x] EXPENSE: decrease chosen sub-balance by amount; account balance logic
        unchanged (existing Transaction rules).
    [x] INCOME: increase chosen sub-balance by amount.
    [x] Account with no sub-balances: no extra field (current UX).
    [x] Store subBalanceId (or equivalent) on Transaction; validate slice
        balance on expense; reverse/adjust on edit/delete.
    Files: transactionModel.js, transactionController.js, finance helpers,
           TransactionCreatePage.jsx, TransactionEditPage.jsx.

H3. Transfers use sub-balance on from/to your accounts
    [x] On transfer create/edit: when From is your account with sub-balances,
        pick source pocket; when To is your account with sub-balances, pick
        destination pocket.
    [x] Same account, different pockets allowed (reallocate inside account).
    [x] “Other” external sender/recipient sides: no sub-balance picker.
    [x] Store fromSubBalanceId / toSubBalanceId on Transfer where applicable;
        validate source slice has enough; update both slices; total account
        balance unchanged for internal moves.
    Files: transferModel.js, transferController.js, TransferCreatePage.jsx,
           TransferEditPage.jsx.

H4. Follow-ups (out of initial scope unless bundled)
    [x] Debt payment: which pocket receives money when account has sub-balances.
    [ ] Dashboard/account detail UI showing pocket breakdown.
    QA: Account with no pockets — forms unchanged. With pockets — cannot
        expense more than slice; transfer moves slice amounts; totals match
        account balance.
