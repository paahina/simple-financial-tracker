SIMPLE FINANCIAL TRACKER
Project Planning Document
=========================

1. PROJECT PURPOSE

A personal financial tracker web application for users to manually record and understand their finances.

The application does NOT integrate with banks, e-wallets, or other financial APIs. Users manually create their financial accounts and manually record income, expenses, transfers, and debt payments.

The primary goal is simplicity, correctness, and useful financial summaries.

2. USER ROLES

SYSTEM_ADMIN
- Administrative role.
- Can manage system-level data and users as defined by the implementation.
- Does not automatically gain unrestricted access to private financial information unless explicitly required by the application's authorization rules.

USER
- Tracks their own finances.
- Creates and manages their own accounts.
- Records income and expenses.
- Transfers money between their own accounts.
- Tracks money owed to them.
- Views dashboards and monthly/yearly reports.

4. CORE PRINCIPLE

Accounts represent where the user's money is held.

Transactions represent money entering or leaving an account through income or expenses.

Transfers represent movement of money between two accounts owned by the same user.

Debts represent money other people owe the user.

Reports are derived from the underlying financial records rather than manually stored totals.

6. NON-GOALS FOR MVP

Do not implement initially:
- Bank API integrations
- E-wallet API integrations
- Investment tracking
- Cryptocurrency
- Credit-card interest calculations
- Automated financial advice
- Complex budgeting
- Recurring transaction automation
- Multi-currency conversion
- Shared household accounts

These can be considered later if the core application proves useful.

7. DESIGN PRINCIPLES

- Keep the application personal and simple.
- Financial totals should be derived from source records.
- Validate all financial input.
- Keep income/expense transactions separate from account-to-account transfers.
- A user can only access their own financial records.
- Prefer explicit business rules over hidden behavior.
